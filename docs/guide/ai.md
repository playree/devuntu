# AIとの連携

> **対象**: 自分の AI ツールから Devuntu を使いたい人、AIエージェントにチケットを任せたい人
>
> - **MCP**: Claude Code などの AI ツールから、自分の権限でチケットを検索・作成・更新・コメントできる
> - **エージェント**: AI専用のユーザーをチケットの担当者にすると、AI が自動で対応して結果を報告する
> - どちらも、ボードの「AI向けコンテキスト」に書いた前提(対象リポジトリ・規約など)が AI へ届く

管理者向けの設定(MCP の公開・エージェントの用意)は [mcp-server.md](../admin/mcp-server.md) と
[agent-runner.md](../admin/agent-runner.md) を参照。

## できること

|              | MCP(自分の AI ツールからつなぐ)              | エージェント(チケットを任せる)                               |
| ------------ | -------------------------------------------- | ------------------------------------------------------------ |
| 動かす人     | 自分。AI ツールに指示する                    | 管理者が用意したマシンで自動に動く                           |
| 権限         | 自分の権限                                   | エージェント用ユーザーの権限                                 |
| 始め方       | AI ツールに Devuntu を登録する               | 担当者にエージェントを選び、承認者がエージェントモードを選ぶ |
| 結果の残り方 | プラン・報告書としてチケットのコメントに残る | 同じ。終わると通知が届く                                     |

**MCP**(Model Context Protocol)は、AI ツールが外部のサービスを道具として使うための共通の仕組み。
Devuntu は MCP サーバーとして動くので、MCP に対応した AI ツールから接続できる。

## AIツールからつなぐ(MCP)

接続先は `<Devuntu の URL>/api/mcp`。接続すると、自分の権限でチケットの検索・作成・更新・コメントができる。
本文やコメントには画像も添付でき、貼られている画像を AI に見せることもできる。

### トークンで登録する(おすすめ)

管理者の設定に関係なく使える方法。

1. `/account` の「MCPトークン」で、名前と有効期限を選んでトークンを発行する
2. 表示された登録コマンドをコピーし、AI ツールを使う端末で実行する(トークンはこのときだけ表示される)

Claude Code の場合は次の形になる。

```sh
claude mcp add --scope user --transport http devuntu <Devuntu の URL>/api/mcp \
  --header 'Authorization: Bearer <発行したトークン>'
```

Codex CLI の場合は、トークンを環境変数へ置いてから登録する(Codex は設定ファイルにトークンそのものを書けないため)。

```sh
codex mcp add --url <Devuntu の URL>/api/mcp --bearer-token-env-var DEVUNTU_MCP_TOKEN devuntu
```

```sh
export DEVUNTU_MCP_TOKEN='<発行したトークン>'   # .bashrc / .zshrc などに残す
```

- トークンは1人10本まで発行できる。端末ごとに分けておくと、失くしたときにその端末の分だけ消せる
- 紛失・漏えいしたときは、`/account` の一覧から削除する(すぐに使えなくなる)。発行し直して登録し直す
- 発行には最近ログインしている必要がある。しばらく前のログインだと再認証を求められる

### ブラウザで認可して登録する

管理者が `OIDC_DCR_ENABLED=true` を設定している環境では、トークンを発行せずに、ブラウザでサインインと同意をするだけで接続できる
(設定されていなければ、[トークンで登録する](#トークンで登録するおすすめ)を使う)。

```sh
claude mcp add --scope user --transport http devuntu <Devuntu の URL>/api/mcp
```

登録後、devuntu のツールを最初に使ったときにブラウザが開く。サインインして同意すると、以降は自動的に継続する
(ブラウザを開けないサーバー上では `claude mcp login --no-browser devuntu`)。

- 許可の取り消しは `/account` の「許可済みアプリ」から行う
- 登録名はトークンの場合と同じ `devuntu`。どちらか一方で登録する
- 登録状況は `claude mcp list`、削除は `claude mcp remove devuntu`

### つながったか確かめる

AI ツールに「devuntu の ping を呼んで」と頼む。自分のメールアドレスが返れば接続できている。
続けて「devuntu のボード一覧を見せて」と頼むと、参加しているボードが返る。

### 頼み方の例

- 「`<チケットのURL>` のチケットを対応して」
  — チケットを読んでプランを投稿し、対応後に報告書をチケットへまとめる。
  受け入れ条件があれば、条件ごとの充足と根拠も記録する
- (プランを作った後に)「このプランでチケットを作成してから対応を進めて」
  — チケットの起票から任せられる
- 「ABC ボードで自分が担当の未完了チケットを一覧にして」
- 「このスクリーンショットを ABC-42 のコメントに貼って」

対応の進め方(着手時に対応中にする → プランを投稿 → ブランチや PR を紐付け → 受け入れ条件の結果を記録 → 報告を投稿)は、
指示しなくても Devuntu から AI ツールへ伝わる。プロジェクトのルール(`CLAUDE.md` / `AGENTS.md` など)や
指示で別のやり方を書いた場合は、そちらが優先される。

### MCP 経由でできること・できないこと

権限は画面と同じで、ボードのロール(オーナー / メンバー)で決まる。ただし、AI が他人の作業を書き換えないよう、
チケットの更新と削除だけは画面より厳しくしてある。

- メンバーは**他人が担当のチケットを更新できない**(未割り当てなら可能。オーナーは制限なし)
- チケットの削除は、オーナー・メンバーともに**自分が作成したチケットだけ**
- メンションを書くと、画面から書いた場合と同じように相手へ通知が届く

使えるツールの一覧と入力の仕様は [mcp-tools.md](../dev/mcp-tools.md)(開発者向け)を参照。

## AI向けコンテキストとテンプレート

ボード設定に書いておくと、AI ツールとエージェントの両方に届く。

- **AI向けコンテキスト** — 対象リポジトリ・規約・用語など、そのボードのチケットに共通する前提(Markdown・8000文字まで)。
  チケットごとに書かなくてよくなる。AI は着手前に読み、チケットに別の指示が無ければ従う。
  編集できるのはボードのオーナーと管理者(プライベートボードは所有者)
- **チケットテンプレート** — 本文・受け入れ条件・タグ・優先度の雛形(1ボード20件まで)。
  「背景 / やること / やらないこと / 確認方法」のような見出しと受け入れ条件を用意しておくと、AI に起票させても形式がそろう。
  AI には「`<テンプレート名>` のテンプレートでチケットを作って」のように頼める

エージェントだけに伝えたい指示(エージェント単位の共通ルール)は、エージェントの「カスタム指示」に書く
([agent-runner.md](../admin/agent-runner.md#カスタム指示))。
AI へのインプットは、この2つと、リポジトリの `CLAUDE.md` / `AGENTS.md` など、そしてチケットの内容になる。

## エージェントにチケットを任せる

管理者が用意した**エージェント**(AI専用のユーザー)をチケットの担当者にすると、
そのエージェントを動かしているマシンで AIエージェントの CLI(Claude Code / Codex CLI)が自動的に起動して対応する。

**担当者に指定しただけでは動かない。** チケット詳細で「エージェントモード」を選ぶ必要がある。
エージェントモードを選べるのは、そのエージェントの**承認者**だけ([エージェントの承認](#エージェントの承認))。
承認者でない人が担当にした場合は「選択待ち」のまま、承認者のダッシュボードと `/agents` に承認待ちとして出る。
担当者を付け替えると、エージェントモードは選択待ちに戻る。

| エージェントモード | 動き                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 選択待ち           | 対象外。エージェントは処理しない                                   |
| プラン先行         | プランをコメントで投稿していったん終了し、返信を受けてから実装する |
| 自動実行           | プランを作らずに対応し、結果を報告書コメントで投稿する             |

迷ったら**プラン先行**にする。プランを読んで「進めて」「ここを直して」と返信すれば、その内容で続きを進める。

処理状態(処理待ち / 順番待ち / 処理中 / 返信待ち / 報告済み / 失敗 / 見送り)はチケット・かんばんのカード・`/agents` から確認できる
(カードに出るのは、エージェントに任せている未完了のチケットだけ。順番待ちは `/agents` には出ない)。
実行が終わると、チケットの作成者へ通知が届く([通知](user-guide.md#通知))。文面は結果に応じて、
プランへの返信待ち・報告の確認待ち・失敗・見送りのどれかと、次にすることを伝える。

エージェントは数分おきに担当チケットを確かめに来るので、モードを選んでから動き出すまで少し時間がかかる。
稼働時間帯や1日の処理上限は管理者と承認者が設定するため、時間帯によってはすぐに動かないこともある。

### 承認と差し戻し

エージェントのプランや報告書には、コメントの下に「承認」「差し戻し」のボタンが出る(チケットを編集できる人のみ)。

| 対象   | 承認                                                   | 差し戻し                                           |
| ------ | ------------------------------------------------------ | -------------------------------------------------- |
| プラン | 定型文で返信し、エージェントがプランどおり実装を始める | 理由を入力して返信し、エージェントがプランを直す   |
| 報告書 | 確認のうえ返信し、チケットを完了にする                 | 理由を入力して返信し、エージェントが追加で対応する |

返答したコメントには「承認」「差し戻し」の印が付く。ボタンは最新のプラン / 報告書にだけ出て、誰かが返信した後は消える。
プランへは、ボタンを使わず普通のコメントで返信しても続きが動く。
報告書の後は普通のコメントだけでは再開しないので、追加で対応させたいときは「差し戻し」を使う。

ボードで自動差し戻しが有効になっていると、紐付いたプルリクエストの CI の失敗やレビュー指摘でも、
報告済みのチケットがエージェントへ自動で差し戻される([連携のオプション](../admin/git-integration.md#連携のオプション))。

### タスクの分割

大きな作業はエージェントに子チケットへ分割させられる。プラン先行のチケットで、エージェントが分割したほうがよいと
判断した場合(または本文で分割を指示した場合)、プランに**子チケットの起票案**(件名・本文・順番・処理方式)が付く。

- 起票案はプランのコメントの下に一覧で出る。「承認」を押すと子チケットが作られ(優先度・タグは親から引き継ぐ)、
  「差し戻し」で理由を返すと、エージェントが起票案を直す
- 処理方式のある子は親と同じエージェントの担当になる。**エージェントモードが付くのは、承認した人がそのエージェントの承認者の場合だけ**で、
  そうでなければ選択待ちで作られる。処理方式の無い子は未割り当てで作られる(人が担当する)
- 承認すると親のチケットはエージェントの処理を終える(報告済み)。子がすべて終わったら、人が親を完了にする
- 子は順番どおりに処理され、前の順番の子が済むまでは「順番待ち」になる(同じ順番の子は並行して処理される)。
  「済んだ」の基準は親の「次へ進む条件」で、親の「親子・関連」から変えられる

| 次へ進む条件                 | 次の順番の子が動き出すとき                                               |
| ---------------------------- | ------------------------------------------------------------------------ |
| 前の順番が完了したら(既定)   | 前の順番の子がすべて完了になったとき                                     |
| 前の順番が報告済みになったら | 前の順番の子がすべて報告済み(または完了)になったとき。確認を待たずに進む |

仕組みの詳細は [agent-runner-internals.md](../dev/agent-runner-internals.md#タスク分割子チケットの起票と順番)(開発者向け)を参照。

## エージェントの承認

`/agents` は、自分が**承認者**に設定されているエージェントのチケットをまとめて確認する画面。
承認者は、そのエージェントにどのチケットを任せてよいかを判断する役割で、管理者が `/admin/agents` で設定する。

- 対象のエージェントを選ぶと、その担当チケットが処理状態つきで一覧表示される
- 行を選ぶと右側にチケットの内容が表示され、エージェントモードをその場で切り替えられる
- 「返答」列から、返答待ちのプラン / 報告書をその場で承認・差し戻しできる。
  ただし返答できるのはそのボードのメンバーだけで、承認者であってもメンバーでなければボタンは出ない
  (承認者はエージェントに任せてよいかを判断する役割で、プランの妥当性の判断はボードのメンバーが行う)
- 完了したチケットは一覧に出ない。処理状態が「報告済み」でもチケットが未完了なら、報告への返答待ちとして表示される

一覧の下では、選んだエージェントの設定(自動運用・カスタム指示・今月の利用・実行履歴)を管理画面と同じ内容で操作できる
([agent-runner.md](../admin/agent-runner.md#画面での設定))。

承認者に設定されているエージェントが1つも無い場合、この画面には何も表示されない。

## うまくいかないとき

| 症状                                 | 確認すること                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| AI ツールから `401` / 認証エラー     | トークンの期限切れ・削除。`/account` で発行し直して登録し直す                                               |
| ブラウザ認可で登録できない           | 管理者が DCR を有効にしていない。[トークンで登録する](#トークンで登録するおすすめ)                          |
| `503` が返る                         | メンテナンス中。しばらく待つ                                                                                |
| 他人が担当のチケットを更新できない   | MCP 経由の制限([できること・できないこと](#mcp-経由でできることできないこと))。担当を外すか画面から操作する |
| エージェントを担当にしたのに動かない | エージェントモードが「選択待ち」のまま。承認者がプラン先行か自動実行を選ぶ                                  |
| モードを選んだのに処理されない       | 稼働時間帯外・1日の上限・ランナーの停止など。承認者か管理者に `/agents` の稼働状況を確認してもらう          |
| 子チケットがずっと「順番待ち」       | 前の順番の子が「次へ進む条件」を満たしていない(既定は完了)                                                  |
