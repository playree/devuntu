# はじめに

> **対象**: 初めて Devuntu を使う人
>
> - サインインすると、自分専用のプライベートボードがすでに用意されている
> - チケットを作って、担当・コメント・メンションで進める。かんばんのカードをドラッグすれば進み具合が変わる
> - 通知は自分で ON にするまで届かない。`/account` の「通知設定」で受け取りたいものを選ぶ

![かんばんボード](../images/board.webp)

## Devuntu でできること

- **かんばんでチケット管理** — バックログ / 対応予定 / 対応中 / 完了 の4レーン。担当者・優先度・期日・タグ・受け入れ条件・親子関係
- **コメントとメンション** — `@` で相手を呼ぶと通知が届く。プラン・報告書の種別で、方針と結果を分けて残せる
- **通知** — メンション・担当の変更・AI の実行結果を、メール / Slack / ブラウザのプッシュ通知で受け取れる
- **AI との連携** — 自分の AI ツールからチケットを読み書きしたり、AIエージェントにチケットを任せたりできる([ai.md](ai.md))
- **GitHub / GitLab との連携** — PR やコミットをチケットに紐付け、PR の状態と CI の結果をチケットで見られる
- **カレンダー** — Google カレンダーの空き時間を、予定の中身を見せずに公開URLで共有できる
- **リモート実行** — 管理者が用意したデプロイなどの処理を、画面のボタンから実行できる

どの機能が使えるかは、管理者の設定によって変わる(使えないものはメニューに出ない)。

## 最初の30分

1. **サインインする** — 管理者から届いた URL の `/auth/signin` を開き、メールアドレスを入れる。
   届いた認証コードを入力するか、パスワードでサインインする(どちらになるかは環境による)
2. **自分の設定をする** — 左のメニューの「アカウント」(`/account`)を開き、タイムゾーンとアバターを確認する。
   次回から楽にサインインしたい場合はパスキーを登録する。表示言語とテーマはメニューの上部で切り替えられる
3. **通知を ON にする** — `/account` の「通知設定」で、メンションと担当の変更だけでも ON にしておく。
   ブラウザに通知を出したい場合は、その端末で「Webプッシュ通知」を登録する([通知](user-guide.md#通知))
4. **ボードを開く** — メニューの「ボード」に参加しているボードが並ぶ。チームのボードが無ければ、管理者かボードのオーナーに追加してもらう。
   自分専用のプライベートボードはいつでも使える
5. **チケットを作る** — かんばんの各レーンの「チケット追加」から、件名を入れて作る。
   完了の基準がはっきりしているなら「受け入れ条件」に1行ずつ書いておく
6. **進める** — 担当者を選び、コメントで相談する。`@名前` で呼んだ相手には通知が届く。
   作業が進んだらカードを右のレーンへドラッグする
7. **共有する** — チケットの表示ID(`ABC-42` の形)をクリックすると共有用のURLがコピーされる。チャットにはこれを貼る

慣れてきたら、[利用マニュアル](user-guide.md)で必要な画面の節を、AI を使うなら [AIとの連携](ai.md) を読む。

## 用語

| 用語               | 意味                                                                                               |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| ボード             | チケットをまとめる単位。チームで共有する「チーム」と、1人に1つの「プライベート」がある             |
| ボードキー         | ボードごとの大文字英数の略号(例: `ABC`)。チケットの表示IDの頭に付く                                |
| 表示ID             | `ボードキー-連番` の形のチケットの番号(例: `ABC-42`)。`/t/ABC-42` で直接開ける                     |
| 受け入れ条件       | 「何ができたら完了か」を1行ずつ書いたもの。人の確認と AI の自己申告の両方を記録できる              |
| 親子・関連         | チケット同士の関係。大きな作業を子に分けたり、同時に見たいチケットを関連付けたりする               |
| プラン / 報告書    | コメントの種別。対応方針(プラン)と対応結果(報告書)を普通のコメントと分けて残す                     |
| AI向けコンテキスト | ボードに書いておく、AI に必ず伝えたい前提(対象リポジトリ・規約など)                                |
| MCP                | AI ツールが外部サービスを使うための共通の仕組み。Devuntu は MCP サーバーとして AI ツールから使える |
| エージェント       | 管理者が用意する AI 専用のユーザー。担当者にすると自動でチケットに対応する                         |
| エージェントモード | エージェントにどう対応させるかの選択(選択待ち / プラン先行 / 自動実行)。選ぶまで動かない           |
| 承認者             | そのエージェントにチケットを任せてよいかを判断する人。`/agents` で担当チケットをまとめて見られる   |
| ランナー           | エージェントを動かしているマシン。数分おきに担当チケットを確かめに来る                             |
| リモート実行       | 管理者が定義した処理(デプロイなど)をサーバー上で実行する機能。実行できるのはアサインされた人だけ   |

## 役割と権限

| 役割                   | 誰がなるか                               | できること(主なもの)                                                                   |
| ---------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------- |
| 管理者                 | 最初に登録した人と、管理者が指定した人   | ユーザー・グループの管理、連携の有効化、エージェントの作成、すべてのボードの構成変更   |
| ボードのオーナー       | ボードを作った人と、オーナーが指定した人 | ボードの構成(メンバー・設定・テンプレート・AI向けコンテキスト・連携)の変更、アーカイブ |
| ボードのメンバー       | オーナーか管理者が追加した人             | チケットの作成・編集・コメント、タグの追加                                             |
| エージェントの承認者   | 管理者が `/admin/agents` で指定した人    | エージェントモードの設定、自動運用の設定、エージェントの利用量の確認                   |
| リモート実行のメンバー | 管理者がターゲットにアサインした人       | そのターゲットのコマンドの実行                                                         |
| リモート実行のオーナー | 管理者がユーザー単位でアサインした人     | 実行に加えて、コマンド定義の画面からの編集(許可されたターゲットのみ)                   |

- チケットの削除は、ボードのオーナーかチケットの作成者だけ
- 自分のコメントは編集・削除できる。他人のコメントを削除できるのは、チケットを削除できる人
- AI ツール(MCP)から操作するときは、他人が担当のチケットを更新できないなど、画面より少し厳しくなる([ai.md](ai.md#mcp-経由でできることできないこと))

## よくある質問

**通知が届かない**

通知は自分で ON にしたものだけが届く。`/account` の「通知設定」を確認する。Slack は自分の Slack アカウントの連携、
Webプッシュは端末ごとの登録も必要([通知](user-guide.md#通知))

**チケットを別のボードへ移したい**

移せない。移したい先のボードで作り直す

**ボードキーを変えたら、共有したリンクが開かない**

ボードキーを変えると、以前の表示ID(`/t/ABC-42` など)は元のチケットを指さなくなる。新しい表示IDで共有し直す

**メニューに「カレンダー」や「リモート実行」が無い**

管理者がその機能を有効にしていないか、自分が使える対象になっていない。管理者に確認する

**エージェントを担当者にしたのに何も起きない**

エージェントモードが「選択待ち」のまま。そのエージェントの承認者がチケット詳細で「プラン先行」か「自動実行」を選ぶと動き出す
([ai.md](ai.md#エージェントにチケットを任せる))

**しばらく前にログインしたのに、操作の途中で再認証を求められた**

トークンの発行や取り返しのつかない操作では、ログインから一定時間が経っていると本人確認をやり直す
