# 利用マニュアル

Devuntu の使い方。画面ごとのアクセス制御の詳細は [screens.md](screens.md) を参照。

## サインイン

`/auth/signin` から、次のいずれかでサインインする。どれが使えるかは管理者の設定による。

| 方法                 | 内容                                                                           |
| -------------------- | ------------------------------------------------------------------------------ |
| メールOTP            | パスワード認証が無効な環境。メールアドレスを入力し、届いた認証コードを入力する |
| パスワード           | パスワード認証が有効な環境。メールアドレスとパスワードを入力する               |
| Googleでサインイン   | Google OAuth が構成されている場合                                              |
| パスキーでサインイン | `/account` でパスキーを登録済みの場合                                          |

メールOTPとパスワードは排他で、どちらが使われるかは環境設定(`DISABLE_PASSWORD_AUTH`)で決まる。
パスワード認証が有効な環境では、2要素認証の設定を求められることがある。
サインイン後は元のURLへ戻る(`?cb=` で保持している)。

## ダッシュボード

`/` はウィジェットを並べたダッシュボード。表示されるウィジェットは次のとおり。

- アプリ情報 / サーバー情報 / リリースノート
- お知らせ(管理者が `/admin/dashboard` で登録)
- リンク(管理者が登録した外部サイトへのショートカット)

「ダッシュボードを編集」から、自分の画面の並びを左右のカラムで入れ替えられる。
初期レイアウトは管理者が設定する。

## ボードとかんばん

`/boards` が参加しているボードの一覧。ボードを開くと `/boards/[id]` のかんばんになる。

レーンは **バックログ / 対応予定 / 対応中 / 完了** の4つで、カードをドラッグしてステータスを変更できる。
同じレーン内での並べ替えもドラッグで行う。

画面上部の絞り込みでは、担当者(未割り当てを含む)・優先度・期日・タグを指定できる。
完了レーンは「完了の表示期間」で指定した期間内に完了したチケットだけを表示する。

「アーカイブ済みも表示」を外している間、アーカイブしたボードは一覧に出ない。
アーカイブしてもチケットは消えない。

### ボードの種類

| 種類           | 説明                                                                 |
| -------------- | -------------------------------------------------------------------- |
| チーム(`team`) | 複数人で共有するボード。メンバーやグループを割り当てる               |
| プライベート   | 1ユーザーにつき1つ、自動で用意される個人用ボード。構成は変更できない |

チームボードのメンバーには `owner` と `member` のロールがある。
ボードの構成(メンバー・タグなど)を変更できるのは `owner` と管理者。

### ボードキーとチケット表示ID

ボードには大文字英数の**ボードキー**があり、チケットの表示IDは `ボードキー-連番`(例: `ABC-42`)になる。
`/t/ABC-42` でチケットを直接開けるので、チャットやメールで共有するときはこの形式が便利。

ボードキーを変更すると、共有済みの表示IDは元のチケットを指さなくなる。
過去に使われたキーの再利用もできない。

### ボード設定

`/boards/[id]/settings` で次を管理する。

- **ボード概要** — 名前、説明、ボードキー
- **ボードメンバー** — ユーザー単位の追加とロール(`owner` / `member`)
- **グループアサイン** — グループ単位の割り当て(変更できるのは管理者のみ)
- **タグ管理** — タグの追加・名前と色の変更・削除
- **デンジャーゾーン** — アーカイブ、ボードの削除(チケットとコメントもすべて消える)

## チケット

かんばんのカード、または `/tickets` の一覧からチケットを開く(`/tickets/[id]`)。

### チケットの項目

| 項目       | 内容                                     |
| ---------- | ---------------------------------------- |
| 件名       | 必須                                     |
| 説明       | Markdown。画像の挿入・貼り付けができる   |
| 担当者     | ボードのメンバーから選ぶ。未割り当ても可 |
| ステータス | バックログ / 対応予定 / 対応中 / 完了    |
| 優先度     | 緊急 / 高 / 中 / 低                      |
| 期日       | 日付。過ぎると期限切れとして表示される   |
| タグ       | ボードごとに定義したタグを複数付けられる |

エージェントを担当者にできるボードでは、ここに「エージェントモード」も表示される
([エージェントにチケットを任せる](#エージェントにチケットを任せる))。

### コメントとメンション

チケットにはコメントを投稿できる。種別は3つ。

| 種別   | 用途                                   |
| ------ | -------------------------------------- |
| 通常   | 普通のコメント                         |
| プラン | 対応方針の提示。主にエージェントが使う |
| 報告書 | 対応結果の報告。主にエージェントが使う |

本文・コメントのどちらでも `@` に続けて名前かメールアドレスを入力すると、候補からメンションできる。
メンションされた相手には通知が飛ぶ([通知](#通知))。

### 一覧から探す

`/tickets` はアクセスできるすべてのボードのチケットを横断して表示する。
キーワード、ボード、ステータス、優先度、担当者、タグで絞り込め、表示IDや期日で並べ替えられる。
検索結果には表示件数の上限がある。

## カレンダーと空き時間の共有

`/cal` は自分のカレンダー。**Googleアカウント連携が前提**で、未連携の場合は連携を促す案内が出る。
管理者が Google 連携を有効にしていない環境では使えない。

「空き時間の共有」を有効にすると、共有URL(`/cal/[id]`)が発行される。

- **共有URLは認証不要の公開ページ**。URLを知っていれば誰でも空き状況を見られる
- 見えるのは「予定あり」の時間帯だけで、予定の件名や詳細は公開されない
- 共有タイトルを設定できる
- URLを再発行すると以前のURLは無効になる。共有をやめるときは無効化する

共有を有効にすると「予定の追加登録」が使えるようになり、毎週固定の予定(曜日と時間帯)を登録できる。
定例会議など、Google カレンダーに入れていない時間を空き時間から除きたいときに使う
(共有を有効にする前は表示されない)。

## 通知

チケット本文やコメントで `@` メンションされると、**メール**または **Slack DM** で通知が届く。

`/account` の「通知設定」で、イベント種別 × チャネルごとに ON/OFF を切り替えられる。
Slack 通知を受け取るには、管理者による Slack 連携の有効化と、自分の Slack アカウント連携の両方が必要
(Slack 側のメールアドレスが Devuntu のものと一致している必要がある)。

Slack に貼ったチケットURLは、閲覧権限を確認したうえでカード表示に展開される。
仕組みの詳細は [notifications.md](notifications.md) を参照。

## アカウント設定

`/account` で次を設定する。

- **アバター** — 独自の画像を設定すると、以降のサインイン時に外部の画像で上書きされなくなる
- **タイムゾーン** — 日時の表示に使われる
- **パスキー** — パスキーの登録・削除。パスキーでのサインインに使う
- **Googleアカウント** — 連携・解除(カレンダー機能の前提)
- **Slack** — 連携・解除(Slack通知の前提)
- **許可済みアプリ** — MCPクライアントなどに与えたアクセスの確認と取り消し
- **通知設定** — 通知のチャネル別 ON/OFF

## AIとの連携

### 自分のAIツールからつなぐ(MCP)

Claude Code などの MCP クライアントから `<Devuntu の URL>/api/mcp` へ接続すると、
自分の権限でチケットの検索・作成・更新・コメントができる。

初回はブラウザが開いてサインインと同意を求められ、許可すると以降は自動的に継続する。
許可の取り消しは `/account` の「許可済みアプリ」から。

登録手順は [mcp-server.md](mcp-server.md#claude-code-への登録) を参照。
管理者が MCP を有効にしていない環境では利用できない。

### エージェントにチケットを任せる

管理者が用意した**エージェント**(AI専用のユーザー)をチケットの担当者にすると、
そのエージェントを動かしているマシンで Claude Code が自動的に起動して対応する。

**担当者に指定しただけでは動かない。** チケット詳細で「エージェントモード」を選ぶ必要がある。

| エージェントモード | 動き                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 選択待ち           | 対象外。エージェントは処理しない                                   |
| プラン先行         | プランをコメントで投稿していったん終了し、返信を受けてから実装する |
| 自動実行           | プランを作らずに対応し、結果を報告書コメントで投稿する             |

処理状態(処理待ち / 処理中 / 返信待ち / 完了 / 失敗 / 見送り)はチケットと `/agents` から確認できる。
エージェントの稼働時間帯や1日の処理上限は管理者が設定するため、時間帯によっては即座に動かないことがある。

仕組みの詳細は [agent-runner.md](agent-runner.md) を参照。

### エージェントの承認

`/agents` は、自分が**承認者**に設定されているエージェントのチケットをまとめて確認する画面。

- 対象のエージェントを選ぶと、その担当チケットが処理状態つきで一覧表示される
- 行を選ぶと右側にチケットの内容が表示され、エージェントモードをその場で切り替えられる
- 初期表示では完了済みを除いた状態に絞り込まれている

承認者に設定されているエージェントが1つも無い場合、この画面には何も表示されない。
承認者の設定は管理者が `/admin/agents` で行う。
