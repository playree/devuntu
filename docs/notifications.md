# 通知

チケットの操作やエージェントの実行結果を、メール / Slack / Webプッシュで知らせる仕組み。
ここでは、通知を使えるようにする運用者向けに、有効にする条件と Slack App の設定、トラブル対応をまとめる。

- 通知はキューを経由して非同期に送る。チケット操作の応答が遅れることも、送信の失敗で操作が失敗することもない
- 操作した本人には通知しない
- 文面は宛先ユーザーの言語で組み立てる。Slack チャンネル宛は既定の言語(`DEFAULT_LOCALE`)に固定

関連するドキュメント:

- 利用者の設定方法: [user-guide.md](user-guide.md#通知)
- 環境変数の設定: [installation.md](installation.md#slack連携) / [installation.md](installation.md#webプッシュ通知)
- 仕組み・実装(開発者向け): [notifications-internals.md](notifications-internals.md)

## イベントとチャネル

宛先は 2 種類ある。個人宛(DM)は各ユーザーが `/account` の「通知設定」で、
Slack チャンネル宛はボードの管理者が `/boards/[id]/settings` の「チャネル通知」で選ぶ。

| イベント                         | 個人宛(メール / Slack DM / Webプッシュ) | Slack チャンネル宛 |
| -------------------------------- | --------------------------------------- | ------------------ |
| メンションされたとき             | ○                                       | -                  |
| チケットの担当者に指定されたとき | ○(指定された本人)                       | ○                  |
| エージェントの実行が終わったとき | ○(チケットの作成者)                     | ○                  |
| チケットが作成されたとき         | -                                       | ○                  |
| チケットが完了したとき           | -                                       | ○                  |

- 個人宛は**オプトイン**。ON にしたイベント × チャネルだけが届く
- Slack は投入直後に届くが、**メールは 5 分ごとに区切ってまとめて 1 通**で送る(最大 5 分遅れる)
- チケットの完了は、完了レーンへ入ったときだけ通知する。GitHub / GitLab の PR / MR マージによる自動完了でも通知する
- メールと Slack は独立して送る。片方が失敗してももう片方は止まらない

## チャネルごとの有効条件

条件を満たさないユーザーや端末は宛先から外れるだけで、エラーにはならない。

### メール通知の前提

`MAIL_SEND` が設定されていることだけが前提で、ユーザー側の連携作業は要らない。
未設定の環境では通知メールは送信を試みずにスキップされる(OTP メールなど他の送信はエラーになる)。

### Slack通知の前提

Slack DM は、次の 3 段がすべて揃ったユーザーにだけ届く。

1. **環境変数** : `SLACK_CLIENT_ID` / `SLACK_CLIENT_SECRET` / `SLACK_BOT_TOKEN` を設定する。
   `SLACK_TEAM_ID` は任意で、設定すると別ワークスペースのアカウントは連携できない
2. **管理者による有効化** : `/admin/settings` で「Slack連携を有効にする」を ON にする。
   「Slack連携を許可するグループ」を指定するとそのグループのメンバーだけ、空なら全ユーザーが使える
3. **ユーザー本人の連携** : `/account` の「Slackアカウントと連携」から連携する。
   Slack のメールアドレスが Devuntu のものと一致している必要がある

ボードのチャンネル通知とリンクのプレビューも 1・2 が前提。Slack App の作り方は [Slack App側の設定](#slack-app側の設定) を参照。

### Webプッシュ通知の前提

ブラウザ / スマートフォンの通知として届く。次の 3 段がすべて揃った端末にだけ届く。

1. **環境変数** : `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` を設定する(生成は [installation.md](installation.md#webプッシュ通知))。
   未設定なら登録の UI ごと出ない
2. **端末の登録** : 通知を受け取りたい端末で `/account` の「Webプッシュ通知」から「この端末で通知を受け取る」を押す。端末ごとに必要
3. **通知 ON** : `/account` の「通知設定」で「Webプッシュ」を ON にする。端末を 1 つも登録していない間はスイッチが出ない

- 通知は HTTPS のオリジンでのみ動く(`localhost` は例外)
- 鍵を入れ替えると、登録済みの端末はすべて再登録が必要になる
- 同じチケットの通知は端末上で 1 件にまとまる

### iOS / iPadOS の制約

- **iOS / iPadOS 16.4 以降**で、かつ**ホーム画面に追加したアプリから開いた場合だけ**受け取れる。Safari のタブからは登録できない
- タブから開いている場合は、画面にホーム画面への追加を促す案内が出る

## ボードごとのチャネル通知

チームボードの出来事を Slack チャンネルへ投稿する。`/boards/[id]/settings` の「チャネル通知」で、
「通知先チャンネル」を 1 つと「通知するイベント」(チケット作成 / チケット完了 / チケットの担当者変更 / エージェント実行結果)を選ぶ。

- 設定できるのはボードのオーナーと管理者。プライベートボードには無い
- 通知先とイベントの両方を選ばないと通知しない
- 個人の通知設定とは独立している。ただし管理者が Slack 連携を無効にすると止まる
- 設定を消した後に発生した分は送られない

### 通知先チャンネルの一覧

- 一覧に出るのは **Bot が招待されているチャンネルだけ**。出てこないチャンネルは、そのチャンネルで `/invite @Devuntu` を実行してからリロードする
- 一覧は 5 分キャッシュするので、招待した直後は現れないことがある
- 招待されていても、投稿が制限されたチャンネル(read-only channel など)では投稿が拒否される。この失敗は画面には出ず、アプリのログ(warn)にだけ残る
- 一覧の取得には Bot スコープ `channels:read` / `groups:read` が要る

## エージェント実行結果の通知

AIエージェント([agent-runner.md](agent-runner.md))の実行が終了したとき(成功 / 失敗 / スキップ)に通知する。開始時は通知しない。

| 宛先             | 誰に届くか                               | 設定                                              |
| ---------------- | ---------------------------------------- | ------------------------------------------------- |
| DM               | **チケットの作成者**(処理を依頼した本人) | `/account` の「エージェントの実行が終わったとき」 |
| Slack チャンネル | ボードを見ている人                       | ボードのチャネル通知の「エージェント実行結果」    |

文面は実行結果よりも、受け取った人が次にすることを伝える。

| 実行後の状態 | 文面の趣旨                                               |
| ------------ | -------------------------------------------------------- |
| プラン投稿   | プランを投稿した。返信で承認・差し戻しをする             |
| 対応報告     | 対応を報告した。内容を確認して承認・差し戻しをする       |
| 失敗         | 失敗した(時間切れ・報告なしの終了を含む)。実行履歴を見る |
| 見送り       | 見送った。チケットのコメントを見る                       |

- チャンネルを設定していなくても DM は送る(宛先ごとに独立している)
- 投稿には表示ID・チケット名・エージェント名・処理種別・結果・所要時間と、エージェントが報告した要約が載る
- ボタンのリンク先はチケット詳細画面。チケットが削除済みの実行は通知しない

## Slack App側の設定

アプリの定義は `slack/manifest.yaml` にある。<https://api.slack.com/apps> の **From a manifest** に貼り付けて作成する
(既存アプリには App Manifest 画面から反映する)。ホスト名の置き換えと、取得した値をどの環境変数へ入れるかはファイル冒頭のコメントを参照。

| マニフェストの項目                                           | 用途                                              |
| ------------------------------------------------------------ | ------------------------------------------------- |
| `oauth_config.scopes.user`                                   | `/account` からの Sign in with Slack              |
| `oauth_config.scopes.bot` の `chat:write`                    | メンション通知の DM 送信とボードのチャンネル通知  |
| `oauth_config.scopes.bot` の `links:read`                    | リンクの検知(`link_shared`)                       |
| `oauth_config.scopes.bot` の `links:write`                   | プレビューの反映(`chat.unfurl`)                   |
| `oauth_config.scopes.bot` の `channels:read` / `groups:read` | 通知先チャンネルの一覧取得(`users.conversations`) |
| `features.unfurl_domains`                                    | 展開対象のドメイン                                |
| `settings.event_subscriptions.request_url`                   | `/api/slack/events`                               |

反映後は以下を確認する。

- Bot スコープを変更したらワークスペースへ**再インストール**する(しないと `links:write` が効かない)。
  再インストールで `xoxb-` が発行し直されるため、`SLACK_BOT_TOKEN` も入れ替えてアプリを再起動する。
  これは Bot 側の作業で、`/account` からのユーザー連携(user スコープ)のやり直しとは別物
- `missing_scope` が出る場合は、上の再インストールと `SLACK_BOT_TOKEN` の入れ替えが済んでいない
- Event Subscriptions の Request URL が **Verified** になっている(Slack が送る `url_verification` に応答している)
- Signing Secret を `SLACK_SIGNING_SECRET` に設定する。未設定ならエンドポイントは 404 を返し、機能ごと無効になる

## Slackでのチケットリンクのプレビュー

Slack に貼られたチケットURL(`/t/<表示ID>` または `/tickets/<チケットID>`)をカード表示に展開する。
カードには表示ID・チケット名・ステータス・優先度・担当者・期限が載る。展開されるのは次をすべて満たす場合だけ。

- URL のオリジンが `BETTER_AUTH_URL` と一致し、そのドメインが `unfurl_domains` に登録されている
- 貼った人が Slack アカウントを連携済みで、Slack 連携を利用できる(管理者の有効化・許可グループ)。利用停止中でない
- 貼った人がそのチケットを閲覧できる。**プライベートボードのチケットは展開しない**(カードはチャンネルの全員に見えるため)
- **Devuntu のアプリが参加している会話**に貼られた。対象のチャンネルで `/invite @Devuntu` するか、アプリとの DM(App の Messages タブ)に貼る。**自分への DM では動かない**

- 1 メッセージあたりの展開は 5 件まで。入力中(送信前)のプレビューでもカードが出る
- Slack から到達できる公開 HTTPS ドメインが必要なので、`localhost` の環境ではイベントが届かない
- Slack は直近の展開をキャッシュするため、同じ URL を貼り直しても再度は展開されない

## 詰まったときに見る場所

| 症状                                           | 確認すること                                                                                                                                                                                    |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 通知設定に Slack / Webプッシュのスイッチが無い | Slack は環境変数と管理者による有効化(許可グループ)、Webプッシュは VAPID 鍵とその端末の登録([チャネルごとの有効条件](#チャネルごとの有効条件))                                                   |
| 通知先チャンネルの一覧に出てこない / 空        | そのチャンネルで `/invite @Devuntu` を実行したか。招待直後は最大 5 分待ってリロードする                                                                                                         |
| チャンネルへ投稿されない                       | ボード設定で通知先とイベントの両方を選んだか / Bot が招待されているか / 投稿が制限されたチャンネルでないか(アプリのログに warn が出る)/ `SLACK_BOT_TOKEN`                                       |
| リンクが展開されない                           | `LOG_LEVEL=debug` にして `slack unfurl skipped` の `reason` を見る(`bot is not in the channel` / `unlinked user` / `no ticket url` / `no viewable ticket`)。オリジン不一致なら `baseUrl` も出る |
| 投入側と配信側のどちらで止まっているか         | `NOTIFY_WORKER_ENABLED=false` にすると通知はキューへ溜まるだけになる。溜まり方で切り分ける                                                                                                      |
| 届かない通知の状態を見たい                     | [operations.md の「通知キューの確認」](operations.md#通知キューの確認)で、キューの行の状態から止まった段階を調べる                                                                              |
| Web プッシュが特定の端末にだけ届かない         | その端末で再登録する。失効した登録は自動で消える。iPhone / iPad は [iOS / iPadOS の制約](#ios--ipados-の制約)を確認する                                                                         |
