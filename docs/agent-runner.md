# AIエージェントの自動運用(Devuntu Agent)

エージェントに担当させたチケットを、AI エージェントの CLI(Claude Code / Codex CLI)が自動で処理する仕組み。
ここでは、エージェントを動かすマシン(ランナー)を設置・運用する人向けに、設定と保守の方法をまとめる。

- 常駐プロセスは無い。cron が 5 分おきにランナー(`devuntu_agent.py`)を起動し、処理すべきチケットがあるときだけ CLI を起動する
- ランナーから Devuntu へ取りに行く方式なので、ランナー側のポート開放は不要
- 1 回の起動で処理するチケットは 1 件。残りは次の起動で処理する

関連するドキュメント:

- チケットを任せる側の使い方: [user-guide.md](user-guide.md#エージェントにチケットを任せる)
- エージェントユーザーの作成・トークンの発行: [mcp-server.md](mcp-server.md#aiエージェント用ユーザー)
- 仕組み・実装(開発者向け): [agent-runner-internals.md](agent-runner-internals.md)

## 動かすホストについて

> [!WARNING]
> **エージェント専用のホストで動かすこと。** 人が普段使うマシンや、エージェントに触らせたくない鍵・認証情報があるホストでは動かさない。

cron からは権限確認に誰も答えられないため、CLI は既定で操作を自動承認する設定で起動する。
チケット本文やコメントがそのままエージェントへの指示になるので、悪意ある(または誤った)チケットから
作業ディレクトリの外のファイル操作や外部通信まで実行され得る。制限したい場合は [CLI の設定](#cli-の設定cli) で絞る。

## セットアップ

Claude Code か Codex CLI から、Devuntu の MCP に接続した状態で「devuntu のエージェントをセットアップして」と頼む。
MCP ツール `get_agent_setup_guide` がそのマシン向けの手順を返し、それに沿って進む。

- 途中で、エージェントにどちらの CLI(Claude Code / Codex CLI)を使わせるかを聞かれる。セットアップを頼んだ CLI と同じでなくてよい
- ランナー本体は `curl <Devuntu の URL>/agent/devuntu_agent.py` で、サーバーと同じ版が取得される

## 画面での設定

管理者は `/admin/agents/[id]`、エージェントの承認者は `/agents` から、同じ内容を設定できる。

| セクション   | 内容                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 自動運用     | 稼働の有効/無効と、動いてよい条件([自動運用](#自動運用))                             |
| カスタム指示 | そのエージェントが常に従う指示([カスタム指示](#カスタム指示))                        |
| 今月の利用   | 予算上限と次の集計リセット、ボード別と合計の実行数・トークン数・コストの表           |
| 実行履歴     | 過去の実行の結果・所要時間・トークン数・コスト・内容(失敗時は終了コードと標準エラー) |

稼働状況(オンライン / オフライン)・最終ポーリング時刻・ホスト名・ランナーのバージョンも表示される。
実行履歴は保持期間と件数の上限を超えると自動で消える([operations.md](operations.md#自動メンテナンス))。
コスト・トークン数を見られるのは管理者とエージェントの承認者だけ。

### 自動運用

条件を満たさないときは、cron で起動されても何もせずに終わる。

| 項目              | 内容                                                                                                                       |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 有効 / 無効       | 無効にすると処理しない                                                                                                     |
| ポーリング間隔    | cron の間隔に合わせる。最終ポーリングからこの 3 倍の時間が経つと「オフライン」と表示される                                 |
| タイムゾーン      | 稼働時間帯・リセット時刻の判定に使う。未設定ならサーバーの既定(`DEFAULT_TIMEZONE`)                                         |
| 稼働時間帯        | 処理してよい時間帯。未指定なら終日。開始 > 終了で日跨ぎ(例: 22:00〜06:00 は夜間のみ)。終了時刻ちょうどは含まない           |
| 1日の処理上限     | 1日に開始できる実行の数。`0` は無制限                                                                                      |
| 上限リセット時刻  | 1日の処理上限を数え直す時刻(既定 5:00)。月の予算も毎月1日のこの時刻で切り替わる                                            |
| 月の予算上限(USD) | 今月のコストが上限に達すると新しい実行を始めない。`0` は無制限。実行中の1回は止めないので、最後の1回ぶんは超えることがある |

Codex CLI はコストを返さないため、Codex の実行は予算に数えない(コストは `-` と表示される)。

### カスタム指示

エージェントへの指示は、置き場所が 2 つある。

| 置き場所                           | 単位         | 向いている内容                                                         |
| ---------------------------------- | ------------ | ---------------------------------------------------------------------- |
| エージェントの「カスタム指示」     | エージェント | 作業の進め方・作法(作業ディレクトリの使い方、コミットや PR の作法など) |
| ボード設定の「AI向けコンテキスト」 | ボード       | 対象リポジトリ・規約・用語など、そのボードに共通する前提               |

ボードの AI向けコンテキストは、同じボードを扱うほかのエージェントや、人が使う MCP クライアントにも届く。
両方に書いた内容が食い違う場合にどちらを優先するかは、カスタム指示に書いておく。

エージェントは GitHub / GitLab にブランチや PR(MR)を作ると、チケットに紐付けるよう指示されている。
ブランチ名の先頭に表示ID を入れる作法(例: `feature/ABC-12`)をカスタム指示に書いておけば、紐付け忘れても Webhook が自動で紐付ける
([user-guide.md](user-guide.md#関連リンクブランチprコミット))。

## config.json

ランナーの設定は `.devuntu-agent/config.json`。トークンを平文で持つので、パーミッションは 600 にする。
パスを相対で書いた場合は `.devuntu-agent` を基準にする。

| キー          | 既定                       | 内容                                                                    |
| ------------- | -------------------------- | ----------------------------------------------------------------------- |
| `base_url`    | なし(必須)                 | Devuntu の URL                                                          |
| `token`       | なし(必須)                 | エージェントトークン                                                    |
| `workdir`     | `.devuntu-agent` の親      | 作業ディレクトリ([ファイルの置き場所と動作](#ファイルの置き場所と動作)) |
| `cli`         | `{}`                       | CLI の設定([CLI の設定](#cli-の設定cli))                                |
| `timeout_sec` | `3600`                     | CLI を待つ上限(秒)。超えたら止めて失敗にする                            |
| `log_path`    | `.devuntu-agent/agent.log` | ログの出力先                                                            |
| `self_update` | `true`                     | 自動更新するか                                                          |

トークンを再発行したら、`config.json` の `token` だけを書き換えればよい(MCP の設定ファイルはトークンを直接持たない)。

### CLI の設定(cli)

| キー        | 内容                                                                                    |
| ----------- | --------------------------------------------------------------------------------------- |
| `cli.kind`  | 使う CLI。`claude`(既定)/ `codex`                                                       |
| `cli.bin`   | CLI のコマンド。既定は `cli.kind` と同じ名前                                            |
| `cli.args`  | CLI に渡す引数。指定すると既定を置き換える                                              |
| `cli.model` | モデル。claude は `--model` のエイリアス(`opus` など)、codex はモデル名(`gpt-5.5` など) |
| `cli.path`  | CLI を探す PATH。セットアップ時に `save-path` で保存する                                |
| `cli.env`   | CLI に追加で渡す環境変数                                                                |

| `cli.kind` | `cli.args` の既定                                    | `cli.model` の既定                             |
| ---------- | ---------------------------------------------------- | ---------------------------------------------- |
| `claude`   | `--permission-mode auto`                             | `opus`                                         |
| `codex`    | `--sandbox danger-full-access --skip-git-repo-check` | なし(`~/.codex/config.toml` の `model` に従う) |

権限を絞る例:

- claude: `--permission-mode acceptEdits`(編集のみ自動承認)や `--disallowedTools` を使う
- codex: 次のようにする。`--skip-git-repo-check` は外さない(外すと動かない)

  ```json
  "args": ["--sandbox", "workspace-write", "-c", "sandbox_workspace_write.network_access=true", "--skip-git-repo-check"]
  ```

  `network_access=true` が無いと `git clone` や依存関係のインストールが失敗する。
  また `~/.npm` や `~/.cache`、`~/.gitconfig` などへの書き込みも弾かれるので、ビルドまでさせる場合は事前に確認する

codex で推論の強さなどモデル以外を変えたい場合は、`cli.args` に `-c model_reasoning_effort="high"` や `--profile <名前>` を足す。
`cli.args` で出力形式(`--output-format` / `--json`)を指定すると、トークン数・コストが記録されなくなる。

## コマンド

`python3 devuntu_agent.py <サブコマンド> [オプション]`

| サブコマンド | 内容                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| `poll`       | 処理すべきチケットを 1 件処理する(cron から呼ぶ)                        |
| `save-path`  | 今のシェルの PATH を `cli.path` に保存する                              |
| `env`        | CLI に渡す環境変数を `export` 形式で出す(手動で CLI を起動して試すとき) |

| オプション        | 内容                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------- |
| `--config <パス>` | 設定ファイル。省略時は環境変数 `DEVUNTU_AGENT_CONFIG`、無ければ `.devuntu-agent/config.json` |
| `--dry-run`       | CLI を起動せず、何を処理するかだけをログに出す                                               |
| `--debug`         | CLI を起動せず、起動コマンドの全体(PATH・作業ディレクトリ込み)を表示する                     |
| `--lock <パス>`   | ロックファイル(既定 `.devuntu-agent/agent.lock`)                                             |
| `--verbose`       | ログを DEBUG レベルで出す                                                                    |
| `--version`       | ランナーのバージョンを表示する                                                               |

`--dry-run` / `--debug` でも最終ポーリング時刻の更新と自動更新は行う(実行履歴には残らない)。
設定に不備があると終了コード 2 で終わる。

## ファイルの置き場所と動作

ランナー本体・設定・ログ・ロックは、作業ディレクトリ直下の `.devuntu-agent/` に置く。

```
<workdir>/
 ├─ .devuntu-agent/
 │   ├─ devuntu_agent.py
 │   ├─ config.json
 │   ├─ agent.log        1MB でローテートし、agent.log.1〜.3 を残す
 │   └─ agent.lock
 └─ (エージェントが clone したリポジトリ)
```

- **作業ディレクトリ(`workdir`)** は特定のリポジトリではなく、必要なリポジトリをその下に clone する基点。
  どのリポジトリを使うかは、チケットやカスタム指示、ボードの AI向けコンテキストからエージェントが判断する
- **複数のエージェント**を同じホストで動かす場合は、作業ディレクトリを分けて、それぞれに `.devuntu-agent/` を置く
- **多重起動**はランナー自身がロックで防ぐ。cron 行に `flock` などを足さない(毎回スキップされるようになる)
- **自動更新**: 起動のたびにサーバーの最新版と比べ、違えば自分自身を書き換えて終了する(その回はチケットを処理しない)。
  失敗しても warning をログに残して処理を続ける。止めたい場合は `self_update: false`
- **PATH**: cron では `claude` / `codex` が見つからないことが多いため、`cli.path` の PATH を補って起動する。
  CLI を入れ直して場所が変わったら、対話シェルで `save-path` をやり直す

## 詰まったときに見る場所

| 症状                                         | 見るところ                                                                                                                                                                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 管理画面の自動運用が「オフライン」のまま     | cron が動いているか、`.devuntu-agent/agent.log`                                                                                                                                                                                             |
| 実行履歴が「失敗」ばかり                     | 履歴の「内容」に終了コードと標準エラーの末尾が入っている                                                                                                                                                                                    |
| 予算を設定したら動かなくなった               | 「今月の利用」のコストが予算上限に達していないか。`agent.log` に `reason=monthly_budget` が出る。翌月の1日のリセット時刻に戻る                                                                                                              |
| 実行履歴のトークン・コストが `-` のまま      | ランナーが 0.8.0 より古くないか / `cli.args` で出力形式を上書きしていないか。codex はコストを返さないので常に `-`                                                                                                                           |
| 実行が「実行中」で止まる                     | エージェントが処理の終了を報告できていない。60分で失敗になる                                                                                                                                                                                |
| チケットが拾われない                         | 担当がエージェントか / チケットのエージェントモードが「選択待ち」でないか / ステータスが完了でないか / ボードがアーカイブ済みでなく、エージェントがボードのメンバーか / 子チケットなら前の順番の兄弟が済んでいるか(処理状態が「順番待ち」)  |
| `/api/agent/status` が 401                   | トークンの再発行で古くなっていないか(1エージェント1本なので再発行は置き換え)                                                                                                                                                                |
| ランナーの自動更新に失敗しているか確認したい | `.devuntu-agent/agent.log` の warning(「最新版の取得に失敗した」等)を確認する。手動で更新したい場合はセットアップ手順の `curl` コマンドを再実行する                                                                                         |
| Slack へ実行結果が届かない                   | ボード設定の「チャネル通知」で通知先とイベント(エージェントの実行)が選ばれているか / 対象チャンネルに Bot が招待されているか(`/invite @Devuntu`)/ `SLACK_BOT_TOKEN`。詳細は [notifications.md](notifications.md#エージェント実行結果の通知) |
