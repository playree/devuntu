# MCP サーバー

> **対象**: Devuntu を運用する管理者
>
> - `/api/mcp` は常に公開されている。利用者が `/account` で発行するトークンで、**設定なしで**接続できる
> - ブラウザでのサインインと同意だけで接続させたい場合は、`OIDC_DCR_ENABLED=true` を設定する
> - AIエージェント用のユーザーとトークンは `/admin/agents` で作る

`/api/mcp` を MCP クライアント(Claude Code / Codex CLI などの AI ツール)へ公開する。
利用者のつなぎ方と使い方は [ai.md](../guide/ai.md)、ツールの一覧(開発者向け)は [mcp-tools.md](../dev/mcp-tools.md)、
認証の振り分け・実装上の判断(開発者向け)は [mcp-server-internals.md](../dev/mcp-server-internals.md) を参照。

## 公開の設定

| 接続のしかた                                 | 必要な設定                       |
| -------------------------------------------- | -------------------------------- |
| 利用者が発行した MCP トークン                | 不要                             |
| エージェントトークン(自動運用)               | 不要(`/admin/agents` で発行する) |
| ブラウザでサインインと同意(認可コードフロー) | `OIDC_DCR_ENABLED=true`          |

- `OIDC_DCR_ENABLED` が制御するのは、MCP クライアントが自分自身を自動で登録する仕組み(動的クライアント登録、DCR)だけ。
  既定の `false` では MCP クライアントが自動で登録できない(`/admin/oidc-clients` で手動登録したクライアントは使える)
- 環境変数だけで有効になり、`/admin/settings` での操作は不要

## 接続の3経路

エンドポイントは `/api/mcp` で共通。どの経路で接続しても、ツールの実装と権限の判定は同じになる。
クライアントに表示されるサーバー名は、人間は経路によらず `devuntu`、AIエージェントは `devuntu-agent` になる。

| 利用者         | 取得方法                           | 寿命                                      | 止め方                        |
| -------------- | ---------------------------------- | ----------------------------------------- | ----------------------------- |
| 人間(トークン) | `/account` の「MCPトークン」で発行 | 発行時に選択(既定90日、無期限も選べる)    | トークンの削除 / BAN          |
| 人間(ブラウザ) | DCR → 認可コードフロー             | `MCP_REFRESH_TOKEN_EXPIRES_IN`(既定180日) | クライアント無効化 / BAN      |
| AIエージェント | `/admin/agents` でトークンを発行   | 既定は無期限(発行時に任意の期限も選べる)  | トークンの再発行 / BAN / 削除 |

## 誰が使えるか

**クライアントを登録できることと、データを読めることは別**。登録しただけでは何も読めない。

- ブラウザの経路は Devuntu へのサインインを要求する。サインインできる利用者だけが認可を完了でき、同意画面が必ず出る
- MCP の認証は Devuntu のログインセッションから独立している。ログアウトやセッション失効(`SESSION_EXPIRES_IN`、既定5日)の
  影響を受けず、リフレッシュトークンの有効期限(`MCP_REFRESH_TOKEN_EXPIRES_IN`、既定180日)まで利用できる。
  強制的に止めたい場合は OAuth クライアントの無効化、またはユーザーの BAN で行う
- ボードやチケットの権限は、接続したユーザーの画面上の権限と同じ。ただし更新・削除は MCP 経由のほうが厳しい
  ([MCP 経由でできること・できないこと](../guide/ai.md#mcp-経由でできることできないこと))
- ユーザーの MCP トークンは同意画面を経由しないが、本人が自分のアカウントに対して発行するものなので
  同意は自明。権限は発行した本人の画面上の権限とちょうど同じ

## ユーザーの MCP トークン

`/account` の「MCPトークン」で本人が発行する長期トークン。利用者向けの手順は [ai.md](../guide/ai.md#トークンで登録するおすすめ) を参照。

- **1ユーザーにつき最大10本**。用途を見分けるための名前を付けて発行し、名前は本人の中で重複できない
- 発行にはログインからの経過時間が `SESSION_FRESH_AGE`(既定24時間)未満であることを要求する。
  古いセッションからは再認証を挟む
- トークンは発行時にしか表示されない(サーバーは平文を保存しない)。紛失した場合は削除して発行し直す
- 期限は発行時に選ぶ。既定は90日で、無期限も選べる
- 失効は一覧からの削除(即時)。恒久的に止めたい場合はユーザーの BAN で、そのユーザーの全トークンがまとめて無効になる
- 一覧の最終利用日時は最大5分ぶん古くなりうる
- ユーザーを削除するとトークンも一緒に消える
- エージェント専用のツールと、ランナー向けの `/api/agent/*` は使えない(エージェントトークン専用)

## AIエージェント用ユーザー

`/admin/agents` で作成する、MCP からだけ使うユーザー。Web ログインは経路を問わず拒否される。
ボードやチケットの権限は人間の利用者とまったく同じで、ボードのメンバーに加えれば担当者として選択でき、メンションの宛先にもなる。

自動運用(Devuntu Agent)での使い方は [agent-runner.md](agent-runner.md) を参照。

### エージェントとして登録する

`/admin/agents` でトークンを発行した際に表示されるコマンドをそのまま使える。CLI(Claude Code / Codex CLI)を
切り替えると、その CLI 向けの登録方法が表示される。この経路ではブラウザでのログインと同意は発生しない。

```sh
claude mcp add --transport http devuntu-agent <BETTER_AUTH_URL>/api/mcp \
  --scope project \
  --header 'Authorization: Bearer ${DEVUNTU_AGENT_TOKEN}'
```

Codex CLI の場合は `.codex/config.toml` に次を足す。

```toml
[mcp_servers.devuntu-agent]
url = "<BETTER_AUTH_URL>/api/mcp"
bearer_token_env_var = "DEVUNTU_AGENT_TOKEN"
```

トークンは設定ファイルへ直接書かず、環境変数 `DEVUNTU_AGENT_TOKEN` を参照する形にしてある。
自動運用のランナーは `config.json` の `token` をこの環境変数として CLI へ渡すので、再発行時に直す場所は `config.json` だけで済む
([agent-runner-internals.md](../dev/agent-runner-internals.md#トークンの渡り方))。人が手動で使う場合は、環境変数を export してから CLI を起動する。

### メールアドレス

`<識別子>@agents.invalid` を作成時に自動生成する。実在のアドレスは入れられず、メールは届かない。
識別子は**作成後に変更できない**(変えると保存済み本文のメンションが解決できなくなる)。
この形にした理由は [mcp-server-internals.md](../dev/mcp-server-internals.md#aiエージェント用ユーザーのメールアドレス) を参照。

### エージェントトークンの運用

- **1エージェントにつき1本**。発行は常に既存トークンの置き換え(ローテート)になり、
  再発行した時点で、前のトークンを使っている接続はすぐに利用できなくなる
- トークンは発行時にしか表示されない(サーバーは平文を保存しない)。紛失した場合は再発行するしかない
- 期限は既定で無期限。発行時に 30 / 90 / 180 / 365 日も選べる
- 恒久的に止めたい場合はエージェントユーザーの BAN か削除で行う
- 一覧の最終利用日時は最大5分ぶん古くなりうる
- エージェントを削除するとトークンも一緒に消える

## 動的登録されたクライアントの管理

`OIDC_DCR_ENABLED=true` の場合に関係する。

- クライアントは利用者ごとではなく**MCP クライアントのインストールごと**に登録される。
  同じ人でも端末が2台あれば2行、設定を消して再追加すればさらに増える
- 増えた行は `/admin/oidc-clients` の「動的登録」セクションから無効化・削除できる。
  無効化は新しい認可を止め、削除は発行済みトークンと同意も一緒に消す
- 利用者本人は `/account` の「許可済みアプリ」から自分の許可を取り消せる
- 登録を受け付けるのは、認可コードが利用者自身の端末へ戻るクライアント(リダイレクト先がループバックなど)だけ。
  外部サーバーへコードを流すクライアントは登録できない([詳細](../dev/mcp-server-internals.md#登録できるクライアントの範囲))
- 既存の OIDC ログイン用クライアントは MCP を使えない。ただし管理画面から新しく作るクライアントは使える

## 詰まったときに見る場所

| 症状                             | 確認すること                                                                                                 |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| ブラウザ認可の登録で失敗する     | `OIDC_DCR_ENABLED=true` を設定して `docker compose up -d` で作り直したか。トークン方式なら不要               |
| `401` が返る                     | トークンの期限切れ・削除・BAN。エージェントの場合はトークンの再発行で古いものが無効になっていないか          |
| ランナーの API が `401`          | エージェントトークン(`devuntu_agent_` で始まる)を使っているか。個人の MCP トークン(`devuntu_pat_`)は使えない |
| `503` が返る                     | メンテナンスモード中([operations.md](operations.md#メンテナンスモード))                                      |
| エージェントがチケットを読めない | エージェントユーザーがそのボードのメンバーになっているか                                                     |
